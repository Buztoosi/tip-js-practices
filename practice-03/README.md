## Задание 1. Исследование DOM и распространения события

| № | Эксперимент | Что сравнить (Прогноз vs Факт) |
| :--- | :--- | :--- |
| 1 | Найти отсутствующий элемент и пустую коллекцию | `querySelector` вернул `null`, `querySelectorAll` вернул пустой `NodeList` (длина 0). |
| 2 | Прочитать `dataset.taskId` у кнопки | До `Number`: строка "23", тип `string`. После `Number`: число `23`, тип `number`. |
| 3 | Нажать «Добавить запись» дважды | Длина исходного массива не изменилась, но `querySelectorAll` показывает новые элементы в DOM. |
| 4 | Нажать на текст «Изменить заголовок» | Выводится строка с тегами `<strong>` как обычный текст, HTML не интерпретируется благодаря `textContent`. |

**Вывод:** Обработчик на контейнере получает событие, потому что оно всплывает от целевого элемента (`span`) к предку (`button`). Использование `closest` позволяет надёжно найти нужную кнопку независимо от того, куда именно кликнули внутри неё.
